# P2 proposed grouping and compatibility checks

Status **PROPOSED / NOT RUN**. This documents the future independent review. It does not amend the accepted P0 evaluation or activate a new protocol. [Frozen P0 evaluation](R2k_Q1v2_INDEPENDENT_EVALUATION.md) · [P1R admission report](../reports/R2k_Q1v2_P1R_REPORT.md)

## Inventory and group closure

1. With authorization, seal a release manifest keyed by archive/variant, sequence and provider pair/frame ID. Include expected, RGB, Thermal and valid-pair counts per sequence, first/last frame and timestamp, duplicate IDs, absent counterparts, corrupt frames, frozen/blank Thermal, calibration state and file headers (dimensions, precision, channels). Preserve original byte SHA256 and maintain a reason ledger, including empty sequences. Pair by provider identifiers and verified sync, never by zipping compressed directory listings. Keep aligned/unaligned counterparts together.
2. Capture metadata must include canonical physical site, scene or route, original uninterrupted session and parent source bounds, platform and camera serial or pseudonym, recording time with timezone, and illumination source. One site, session, continuous take or repeated/overlapping route is one linked component. Different devices, different tracked objects or different lighting never split an otherwise shared component. Record device as a stratum. Shared hardware alone does not link unrelated sites.
3. Before any frame subsampling, check original digests against both modalities, aligned/unaligned releases, RGBT234/RGBT210 where authorized, frozen MFNet digest inventories and available other historical manifests. Do not open official test pixels. Ask for source clip crosswalks and compare adjoining cuts, repeated camera paths and backgrounds. Run a separately frozen, CPU-only candidate retrieval plan using authorized flipped/re-encoded/crop-aware thumbnails or fingerprints for both modalities, across all release strata. An independent pair of reviewers checks backgrounds, repeated tracked instances, adjacent cuts and uncertain matches without quality scores. Generic object classes and similar filenames only nominate comparisons. Unresolved credible shared acquisition prevents counting affected groups as independent. Document exclusions, comparisons not possible under current rights and the recovered review coverage. Do not publish the underlying images.
4. Union the confirmed links transitively, archive sorted node/edge lists and reasons, assign each component a stable identifier from its sorted source keys, and have a separate reviewer confirm the frozen roster. Exclude implicated historical matches and unresolved leakage before counting. No tracking split, camera number, release folder or adjacent frame starts a new group by itself.
5. Use provider capture-based daytime/nighttime tags or timestamp/timezone and location with a previously frozen rule. Where only independent documentary context exists, two reviewers may assess whether it establishes acquisition lighting. Disagreements, ambiguous twilight or indoor cases, or appearance-only guesses remain unknown and require further evidence under P0. Low Illumination, folder names, filenames, FFC and model outputs do not supply labels. A mixed group can contribute supported frames to both strata and remains a single resampling unit. Report overlap between strata. Label missing support `INSUFFICIENT_METADATA`.
6. Count only groups with verified eligible intact, paired and registered data. The frozen local synthetic Gaussian target is generated on the intact Thermal image. Record valid 96×96 ROI support with margin 12, two fixed kernel/sigma pairs (7, 1.6) and (17, 4.0), frozen seed policy and matched RGB. Exclude input pairs for documented capture defects using predeclared rules, independently of the outcome score. Use at least 40 groups overall, 15 daytime, 15 nighttime and 15 with positive synthetic support. Track actual counts as unknown until reviewed. Natural target motion blur, camera motion, global Thermal blur and physical defocus each require distinct evidence and never substitute for the main synthetic ROI.
7. Lock selection rules, reviewed groups, strata, exclusion decisions, manifests and hashes. The only work after data delivery covered by this preflight is local admission. Real evaluation requires independent approval.

## Conditional R2k-Q1v2.1 proposal for 630×480 LasHeR input

If the authorized native export proves to be aligned 630×480 single-channel uint8 Thermal paired to compatible RGB on that same plane, the default P0 validator must still reject it on shape. Candidate v2.1 would read both at native resolution, preserve decoded Thermal sample values, apply only the existing RGB grayscale decoder, and use origin (0, 0), grid offset 4 and stride 8. Native sampling then gives 79 × 60 points (x=4…628, y=4…476) with every in-grid point retained. No interpolation, padding, new intensity mapping or feature-scale change is proposed. Recompute legal centers geometrically on the smaller plane using the same ROI size, margin, kernel and seed policy. Require documented full-plane pair registration beforehand. Target-local homographies, invalid margins, other encodings or mixed resolutions would still need independent decisions and may leave the source blocked. Do not synthesize missing image context.

Before access to external holdout frames for model evaluation, separately preregister the coordinate and ROI mapping, kernel boundary behavior, support audit, release variant, sampling, acceptance and report labels. Validate the engineering on synthetic fixtures plus an original Fit/Calibration-only coordinate proxy formed by retaining the first 630 columns of both modalities. Use no old Q1 Holdout and no external Holdout for selection. Keep all model parameters, thresholds and scientific endpoints fixed. Report resulting coverage and camera/intensity distribution shift as transfer limitations. This candidate is a separate evaluation protocol and has neither been implemented nor approved. TartanRGBT would require its own proposed input and registration-support protocol.
