## 误差来源

- **Δ 与 softplus。** 用原 CUDA 的零记忆、单位输入注入测得有效 Δ。相对 PyTorch 最大偏差为 4.77e−7，混合比 0.000966。将实测 Δ 输入顺序参考仍有 47 个读出超限。
- **指数与注入。** 在最大混合比位置的分量 0，CUDA 的 `exp2(Δ·(A·log₂e))` 为 0.9954743981，PyTorch 的 `exp(Δ·A)` 为 0.9954745173，改用 exp2 后与该点 CUDA 值一致。最大绝对差位置的注入 `(Δ·x)·B` 与 CUDA 一致，交换乘法顺序改变约 1.49e−8。顺序参考的注入次序变体仍有 49 个超限元素。
- **前缀递推。** Triton 与 CUDA 逐步状态的最大混合比为 0.02587。原 CUDA 使用 CUB 并行组合，Triton 使用自己的分块前缀，独立参考按时间步顺序计算。逐步状态、两种 CUDA 观测方式及顺序参考的偏差显示这些算术分组有影响。固定案例中换用 CUDA 状态后，25 个超限读出降至零。
- **读出与直接项。** 原 CUDA 先置入 `D*x`，再按状态索引累加。两处极值位置的直接项与原 CUDA 的零 C 探针一致，最大混合比处为 2.97722054。固定调用中 PyTorch `addcmul` 和分离乘加的实测统计相同，因此继续使用显式 FMA 验证读出。最大混合比处各项绝对值之和为 262.70163，最终输出绝对值仅 0.01156467，数值抵消放大了微小状态差相对于输出的比例。

这些观测支持 FP32 递推算术差异与读出抵消共同造成阈值失败。各算术变体仅切换指定操作，尚未精确分配 CUB 与 Triton 每个树节点的误差贡献。

## 修复与 Pilot

采用原 CUDA 的状态基向量读出和显式 FP32 FMA 逐状态累加。独立参考以 FP64 计算单项乘加，再逐项舍入为 FP32。Clean 与 corrupt 原始端点保留 native 输出，混合条件按各自的 `h/C/D*x` 组合重构。全部检查沿用原阈值。首次修复执行因 Triton 2.2 的 FMA API 名称错误在合成预检退出，改用本版本的 `tl.math.fma` 后重新执行。[初次预检日志](evidence/r2f/pilot-triton-api-failed.txt)

合成预检覆盖长度 33、300、1,200、2,067，状态维度 4 和 16，分组 1、2、4，输入幅度倍率 0.01 至 2。2,067 步案例跨 CUDA 分块边界。随后 seed 3407 的 SSM、CNN、Attention 各完成原定 12 图。共享编码器和解码器每次前向分别记录 30 和 12 个调用，覆盖四方向。SSM 额外覆盖四尺度 CrossMamba 的 8 个调用和 ConcatMamba 的 4 个调用。上游扫描排序与特征坐标映射使用坐标哨兵逐项核对。[合成预检](evidence/r2f/synthetic-replay.json) · [布局及证书](evidence/r2f/pilot)
