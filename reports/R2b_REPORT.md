## 真实扫描路径与状态定义

上游 `models/encoders/dual_vmamba.py:100–101` 在每个尺度先调用 CrossMamba，再将两路结果交给 ConcatMamba。四尺度特征网格为 120×160、60×80、30×40、15×20。

| 模块 | 固定上游实际路径 | CUDA 调用与顺序 |
|---|---|---|
| CrossMamba | `CrossMambaFusionBlock → CrossMambaFusion_SS2D_SSM → Cross_Mamba_Attention_SSM → selective_scan_fn_v1 → SelectiveScanFn.forward → selective_scan_cuda_core.fwd` | 每尺度两次，RGB 和 Thermal 各一条行优先序列，`nrows=1`。RGB 路用 RGB 的输入与状态更新参数，使用 Thermal 的 `C_t` 读出。Thermal 路反之。 |
| ConcatMamba | `ConcatMambaFusionBlock → ConMB_SS2D → forward_corev2_multimodal → cross_selective_scan_multimodal_k2 → SelectiveScan.forward → selective_scan_cuda_core.fwd` | 每尺度一次分组调用，`nrows=4`。组 0 将 RGB 与 Thermal 行优先拼接，组 1 将整个拼接序列逆转。读出逆转合并后进入归一化、跨模态门控和输出投影。 |
| 上游四方向 SS2D | `CrossScan → cross_selective_scan → SelectiveScan.forward` | 行优先、列优先及其反向。用于合成一致性及坐标映射验证，以上两种融合模块分别按自己的真实方向运行。 |

每步的内部循环状态为 `h[t] = exp(Δ[t] A) ⊙ h[t−1] + Δ[t] B[t] u[t]`，初始状态为零，读出为 `y[t] = C[t] · h[t] + D u[t]`。这里 `Δ[t]` 是加入 bias 后的 softplus 步长。Triton 参考逐时间步物化实际 `h[t]`，用块前缀组合加速，短序列另用逐步顺序实现交叉验证。上游 CUDA 返回的块缓存由每个状态坐标的乘性前缀和加性前缀交错构成，后者是零初始化下的块末 `h[t]`。本轮直接比较该加性槽和 native scan 的 `y[t]`。普通模块 Hook 仅给实际 CUDA 调用标注模块名称和网格，并测下游输出。

Triton 2.2 不支持 tuple associative scan，第一次编译失败已保留。随后把两个 FP32 位模式无损打包为单个 uint64，组合时解包后仍用 FP32 递推。重跑的合成数值审计通过四方向、batch 1/2/3、长度 1/33/300/1029/1200/2067、`nrows=1/2/4`，含 CUDA 2048 步分块边界。误差闸门同时检查逐元素 `2e−5 + 2e−4|native|`、相对 RMS ≤ `2e−5`、峰值归一化误差 ≤ `3e−5`。[合成日志](evidence/r2b/synthetic-gpu.txt) · [首次编译失败](evidence/r2b/synthetic-triton-tuple-unsupported.txt)

## 时间映射与干预

坐标从零开始。令网格高宽为 `H,W`，`L=H×W`。Cross 每个分支的第 `t` 步对应 `(t//W, t%W)`。Concat 正向令 `q=t`，逆向令 `q=2L−1−t`，模态为 `q//L`（0 RGB、1 Thermal），坐标由 `q%L` 行优先解码。四方向映射和 Concat 双方向在四个实测网格上用上游函数及坐标哨兵校验。格点像素区间按输入尺寸整除特征网格定义，描述扫描索引对应的几何格点；模型卷积和编码器的实际感受野可以更大。

主干预固定 `concat.2` 逆向组 `t=1199`，对应 Thermal 网格 `(0,0)`。下一步 `t=1200` 对应 RGB 网格 `(29,39)`。在 native CUDA 基础输出上加参考递推产生的状态读出差。干预时将相同样本、方向及时间的 clean 状态赋给 corrupt 更新后状态，等价于从该步开始传播齐次差分 `Δh[t]=h_clean[t]−h_corrupt[t]`。用独立的显式状态重置全轨迹核对该差分法。干预步之前及另一个方向的差分精确为零。错误时间对照同样复制 clean 状态，但在 `t=0` 的 Thermal `(29,39)` 执行，远早于模态边界。由于编码器的空间感受野，该对照也可能产生非零响应。

Pilot 在固定 12 图上通过。所有 clean/corrupt 预测均复现 R2a。两类各 12 次 Identity 以及清理 Hook 后的 12 组 clean/corrupt 复跑均逐位一致。主替换在 12/12 图改变后续状态、scan 读出、融合输出和 logits，1/12 图产生 1 个 argmax 像素翻转，达到预先设定的扩展闸门。错误时间对照也在另一张图翻转 1 个像素。Pilot 耗时 44.706 s，PyTorch 峰值分配约 1.64 GiB。[Pilot 日志](evidence/r2b/pilot-gpu.txt) · [逐图证据](evidence/r2b/pilot/images.jsonl)

## 157 图状态实验

全量 157 图逐一复现 R2a clean 与 corrupt 的预测哈希和统计，clean 总体 mIoU 61.1498%，主遮挡 60.7577%。Clean 与 corrupt 共审计 3,768 次实际 fusion CUDA 调用。全量 scan 读出的最大绝对偏差为 `1.91e−6`，最坏相对 RMS 为 `1.71e−7`。CUDA 块末状态的最大绝对偏差为 `1.01e−6`，最坏相对 RMS 为 `5.75e−7`。全量命令耗时 168.433 s，PyTorch 峰值分配 1.64 GiB，模型前后指纹一致。每张图仅在本次前向期间保存所需状态；归档只含时间窗标量、坐标、计数、混淆矩阵、哈希和日志。[全量证书](evidence/r2b/full/certificate.json) · [GPU 日志](evidence/r2b/full-gpu.txt) · [数值审计](evidence/r2b/analysis.txt)

## 非 SSM 对照与后续正式协议

**A．冻结其余权重的临时接入。** CNN 使用通道投影、深度卷积和残差，Attention 使用完整网格 query、每模态固定 8×8 池化 key/value、四头注意力和残差。两种替换都通过双输入 BHWC 接口、Cross 双输出、Concat 单输出的测试。各自在 R1g 固定 checkpoint 其余模块上临时运行一张图，均产生有限的 `[1,9,480,640]` logits。此处的替换层是新初始化的，只作工程检查。原模型参数和 checkpoint 指纹保持一致。[冻结接入记录](evidence/r2b/control-frozen-interface.json)

**B．同初始化可训练性与资源。** 三臂以同一 VMamba-T checkpoint 和相同的初始 Sigma 参数指纹构建，CNN/Attention 融合层按相同固定种子新初始化。三臂使用 R1g 训练集同一首个采样窗口、相同预处理、CE、FP32、microbatch 1、累积 8、AdamW 及恒定 `lr=6e−5`。各完成一次优化器更新，所有参数张量有非零有限梯度，优化器状态覆盖完整，两类融合层均发生更新。初次启动在读取训练配置时退出，未开始 GPU 更新；改用 R1g 实际继承的 R1d 训练参数后重跑成功。[训练可行性记录](evidence/r2b/control-trainability.json) · [GPU 日志](evidence/r2b/controls-gpu.txt) · [配置预检失败日志](evidence/r2b/controls-config-preflight-failed.txt)

|---|---:|---:|---:|---:|---:|---:|

GMAC 是融合部分可直接计数的线性投影、卷积和注意力矩阵乘累加，SSM 状态更新数另列，池化、激活、归一化及其他算子未计入。三臂共用仍含 SSM 的编码器与解码器，因此这是融合层对照。峰值为 PyTorch 分配量。按单次更新乘 785 粗估，三臂各约 72、44、47 分钟，共约 2.7 GPU 小时，另计验证、评估和保存。单窗口时延受热身和样本影响，R1g 历史的 SSM 五轮训练实际约 46 分钟。实测显存支持短程训练，整套三臂五轮及评估超出本轮的一次更新资源检查预算。

正式对照应以 seed 3407 分别从官方 VMamba-T 分类初始化重新构建三臂，检查公共参数初始哈希一致。每臂使用同一冻结的 R1g 1,254 条训练记录、157 张验证图、同一数据顺序与 FP32 配置。保持 156 个 8 样本窗口和一个 6 样本尾窗，按实际有效像素归一化，每轮 157 次更新，五轮共 785 次。使用原预处理、CE、相同 AdamW、完整覆盖、恒定学习率，以预先固定的第 5 轮为主结果。逐轮保存训练损失、验证指标、时间、显存、设备与 checkpoint 指纹，模型保存在仓库外。

正式评估在同一验证图上复跑 R2a 全套冻结条件，包含中心遮挡、三个位置的 Gaussian σ20 和种子 3407/3408/3409、局部右移 dx8 及输入 Identity。用相同 54 组、10,000 次共享抽样计算三臂 clean/corrupt 内部配对与跨臂率差，汇报 clean 性能、区域外新增、纠正、净增、距离带分歧和各臂参数量、计算量与累计训练耗时。三臂当前参数量与计算量不同，即使匹配训练预算，比较也只说明所选融合架构的差异，机制特异性还需考虑容量差异。官方 test 图像不用于评估或选模。
